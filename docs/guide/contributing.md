# 补充资料

谢谢你愿意把自己的积累留给后来的人。可以从一份笔记、一个实验步骤、一处错误或一个链接开始。

## 通过 Issue 分享

打开[资料补充表](https://github.com/HustCAteam/Hust-LearningCode/issues/new?template=resource.yml)，填写资料名称、课程、用途、来源和希望展示的署名。希望补充的是群内文件时，一同写下原始文件名、所在文件夹和上传日期，方便找到对应版本。

## 通过 Pull Request 补充

1. 找到对应主题目录；课程入口在 `data/courses.json`，群内独立专题在 `data/topics.json`。
2. 把文件放入“主题 / 课程标识 / 资料类型”目录。
3. 在 `data/materials.json` 登记原名、来源、上传日期、文件路径、作者、上传者与整理者。
4. 运行 `npm run generate`、`npm run check` 和 `npm test`。
5. 在 Pull Request 中说明新增内容、适用课程和署名方式。

课程页由结构化目录生成，改动课程说明时编辑 `data/courses.json`；独立专题说明编辑 `data/topics.json`。学习路线与经验文章直接编辑 `docs/guide/` 中的 Markdown。

## 文件命名

采用 `课程标识__资料类型__主题__版本.扩展名`，例如：

```text
006-操作系统/operating-systems/notes/
  operating-systems__notes__进程同步__2026.pdf
```

| 字段 | 写法 |
| --- | --- |
| 课程标识 | 与 `data/courses.json` 或 `data/topics.json` 中的 `id` 一致 |
| 资料类型 | `notes` 笔记、`slides` 讲义、`lab` 实验、`exercise` 练习、`guide` 指南、`talk` 分享、`source` 源码 |
| 主题 | 能直接看懂内容的短标题 |
| 版本 | 使用资料标明的年份或版本；缺少版本时写 `undated` |

上传时间与内容版本分别记录。文件改名时保留原名，后续仍然可以追溯群内的原始分享。

Office 材料可转换为 PDF 阅读版，沿用原文件名登记 `originalName`，设置 `archiveExtension: ".pdf"`，并在 `originalSha256` 保留原件摘要。`sha256` 对应实际归档的阅读版。转换后核对页数、文字与图示，在用途说明中记录转换方式；原件保留在本地 `inbox/originals/`。

## 保持资料好找、仓库轻便

优先收录能直接帮助学习的笔记、讲义、实验指导、源码和分享材料。软件安装通过官方发布入口获取；大型课程材料、视频和数据集使用原始下载链接。群文件根目录从 2019 年起整理，更早的经典材料在确认具体用途后单独登记。

导入工具会计算 SHA-256，识别同内容文件。单个文件默认控制在 10 MiB 内，仓库内容目标控制在 80 MiB 内。更大的资料可在课程说明里添加原始入口，并注明容量和用途。

## 把贡献留下来

原作者、上传者和整理者分别记录。你可以使用名字、网名或 GitHub 用户名，也可以选择“匿名贡献者”。署名会展示在资料目录和相关课程页。补全历史来源时，也欢迎将当时分享资料的群友一并补上。

谢谢每一位持续分享、解释、补充和纠错的朋友。这些细小的积累会一起变成更容易使用的学习资料。
