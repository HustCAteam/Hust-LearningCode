# 工具与学习习惯

先让常用工具服务于手头的学习：编辑代码、运行程序、看懂报错、记录修改。随着项目变复杂，再逐渐增加构建、测试和自动化。

| 需要完成的事 | 工具与学习入口 | 练习 |
| --- | --- | --- |
| 在终端中工作 | [Missing Semester](https://missing.csail.mit.edu/) | 查找文件、管道组合、重定向输出 |
| 保留代码变化 | [Pro Git](https://git-scm.com/book/zh/v2) | 做一次小提交，查看 diff，恢复自己的实验改动 |
| 理解编译过程 | [GNU Make 手册](https://www.gnu.org/software/make/manual/) | 为多文件程序写构建规则 |
| 定位运行错误 | [GDB 文档](https://www.sourceware.org/gdb/documentation/) | 设断点、看栈、检查变量与内存 |
| 建立可复现工程 | [CMake 教程](https://cmake.org/cmake/help/latest/guide/tutorial/) | 从一个可执行程序逐步加入库和测试 |
| 使用 Linux 环境 | [Linux man-pages](https://www.kernel.org/doc/man-pages/) | 阅读一个命令和一个系统调用的手册 |

## 保存一个好问题

记下预期行为、实际行为、最小代码、完整命令和第一条关键报错。把自己已经试过的办法也写上，交流时就能更快进入问题本身。

群友 QQ昵称、？！区区！？ 分享过[《提问的智慧》](https://github.com/ryanhanwu/How-To-Ask-Questions-The-Smart-Way)。感谢他们把这份阅读带到群里；这里连接持续维护的中文版本，作者为 Eric S. Raymond、Rick Moen，中文翻译与修订署名见原项目。

## 保存一次实验

一个小实验目录可以包含源代码、运行说明、输入样例、结果和简短复盘。版本号、执行命令和运行环境写进 README，过一段时间回来仍然能接着做。

## 用自己的话解释

读完一段材料后合上页面，画一遍数据如何流动，或者写一个最小例子。解释不顺的地方常常就是下一次阅读的起点。
